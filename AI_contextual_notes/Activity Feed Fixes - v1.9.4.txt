# Activity Feed Fixes - v1.9.4
**Date:** 03 February 2025
**Version:** v1.9.3 → v1.9.4

## Overview
Fixed issues with the Activity Feed not displaying search stages and added user-friendly error messaging when no matching releases are found.

## Issues Identified

### Issue 1: "Searching" stage never appeared
**Cause:** Mismatch between log message format and parser regex.

- **Grabber logged:** `Searching for: Practice 3 - Round 22 Las Vegas`
- **Parser expected:** `🔍 Searching: Round 22 Las Vegas - Practice 3`

**Fix in `f1_grabber.py` (line 673):**
```python
# Before
logger.info(f"Searching for: {session_type.display_name} - Round {round_num} {venue}")

# After
logger.info(f"🔍 Searching: Round {round_num} {venue} - {session_type.display_name}")
Issue 2: Multi-word venues not parsed correctly
Cause: Regex used (\w+) which only matches single words.

Log: Round 22 Las Vegas - Practice 3
Regex captured: venue = "Las" (missing "Vegas")
Fix in f1arr_webui.py (lines 956 and 965):

# Before
m = re.search(r'Round (\d+) (\w+) - (.+)', message)

# After  
m = re.search(r'Round (\d+) (.+?) - (.+)', message)

Issue 3: "Found candidates" was debug level
Cause: Message logged at logger.debug() so didn't appear in standard logs.

Fix in f1_grabber.py (line 688):

# Before
logger.debug(f"Found {len(all_results)} raw results")

# After
logger.info(f"📋 Found {len(all_results)} candidates for Round {round_num} {venue} - {session_type.display_name}")

Log Message Format Reference
For the activity feed parser to work, log messages must follow these formats:

Stage	Log Format
Searching	🔍 Searching: Round {num} {venue} - {session}
Found	📋 Found {count} candidates for Round {num} {venue} - {session}
No results	❌ No candidates: Round {num} {venue} - {session}
Grabbed	✅ Grabbed: {prefix} {venue} {session}
